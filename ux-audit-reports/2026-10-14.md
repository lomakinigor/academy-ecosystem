# Проверочная админ-компоновка мероприятий

Запоминание входа / совладельцы: checkbox перед submit, label нажимается целиком
(44px), предупреждение 90 дней / чужое устройство 8 часов / явный выход.
Owner действия с подтверждением, первичный защищён, последнего снять нельзя;
ошибка отображается role=alert, pending блокирует обе операции. Общая палитра сохранена.
Browser-проверка desktop/phone новых форм пока не выполнена (нет browser tools).
Отсутствует полный quality reference: числовой release gate не заявляем; только preview.

Пакетный лимит мест: ответ AI нормализуется до положительного целого либо null,
все выбранные строки повторно нормализуются перед первой записью. Нет лишних надписей,
реальные лимиты сохраняются, ноль не блокирует сохранение отсутствующего лимита.
179 web tests и TypeScript green. Данные пользователя не переписаны, UI геометрия неизменна.
Только preview; общий числовой release gate и ограничения атомарности batch остаются.

Public исправление: выбор филиала скрыт без удаления branchmodel; AgendaList показывает каждую занятую дату многодневного события, badge соответствует секции. Все карточки ведут на исходныйeventID, count уникальный; период обрезает повторения. Без DBзаписей. Числовой UXgate прежний, preview для просмотра, maindomain не менять.

Необязательное окончание: ручная форма не требует поле и не подставляет +2 часа;
batch принимает пустое окончание; API хранит null. Карточка показывает только начало,
без «не указано», тире или фиктивной длительности. Существующие диапазоны/all-day сохранены.
Неизвестная длительность не участвует в точной проверке пересечений; это ограничение MVP.
172 web tests green, nullable-aware API/typecheck проверены. Только preview,
общий числовой release gate остаётся неподтверждённым из-за отсутствующего reference.

Плотность по запросу владельца: одинаковые80pxдни, подписи24pxбез плашек44px, внутренний scroll при>2events. Keyboard focus остаётся, accessible fulltitles сохранены. Tradeoff меньшие touch targets; preview для согласования, не заявлять полный UXgate пройденным. API/DB не меняются.

Краткие подписи: вместо count отдельные кнопки событий с44pxвысотой, только короткое слово, длинные truncate; fulltitle в accessible name и title. Дата отдельной кнопкой create. Nullablecalendar_title хранит override без изменения publictitle; fallback эвристический и исправляемый. 165web tests green, TypeScript green; API124green, дополнительный contract test nullable/max40 добавлен. Проверка мобильного рендера требует входа; maindomain не переключать, прежние release blockers остаются. UX-audit без числовых процентов: утверждённая шкала недоступна.

Уточнение: компактный календарь в7фиксированных колонок Пн–Вс, пустые ячейки перед первой датой. Только дата и count; занятой день отличается цветом и числом, сегодня кольцом. Один event сразу editor, несколько выбор, пустой день create. Служебные counts/status перенесены в editor. Весь день единая метка; поселение включает её при вводе с возможностью ручного отключения. Component tests проверяют offset/count/0–1–many и override. Browser-проверка новой версии ещё требуется. Числовой release gate и ранее перечисленные общие blockers остаются без изменений.

Scope: admin/calendar только. Убраны клиентские фильтры/Sidebar, месячное окно с недельной группировкой, full-width mobile cards, явные weekday/weekend; direct manual/batch actions и создание на день. Manual mobile fullscreen со sticky save/cancel. Title manual, type/speaker dropdown, inline add speaker прежний. Тimestamps в карточке, counts confirmed/waitlist, warning места. Без финансов/маркетинга/Mini App.

Технический gate:160 web tests и124 API tests, TypeScript оба green. Windows Node завершил параллельный API-run с3221225477; повтор sequential maxWorkers1 прошёл все124. Полная утверждённая шкала quality-principles-reference.md отсутствует; проценты не выдумываем. Регистрационные release blockers не устранены, main domain не переключать. Только проверочная публикация по запросу владельца. Browser360/desktop проверка после входа обязательна.

Риски: один филиал — время Екатеринбурга; будущие филиалы с другими timezone требуют отдельных настроек. Статус отображается из текущих данных, publishing workflow не добавлен. AI grounding имени fail-closed: несовпадение полного имени с исходным текстом требует ручного выбора. Capacity booking flow пока прежний (включает WAITLIST при серверной проверке лимита); карточка показывает подтверждённые места отдельно, этот прежний flow не считать исправленным.

Browser после входа:desktop1280/mobile360. Страница и fullscreen manual dialog без horizontal overflow (345/345 и343/343). Sticky footer имеет доступные44px+кнопки; выбранная15октября дата подставлена без сохранения. Сдвиг±неделя проверен для forward21октября, Сегодняreset14октября. Публичный release gate не меняется; UX карточек теперь доступен владельцу для согласования. Мобильное верхнее меню горизонтально прокручивается; можно рассмотреть компактную navigation позже, не расширять current scope.

## UX-аудит: публичная запись, админ-выход и клиенты MVP

Дата: 2026-10-14. Основание: текущие компоненты, tests и ранее присланные
desktop/mobile скриншоты. Это code-аудит для проверочной публикации, не замена
живой проверки на телефоне.

| Принцип и критерий                    | Балл | Краткое обоснование                                                                    |
| ------------------------------------- | ---: | -------------------------------------------------------------------------------------- |
| Дизайн: визуальная иерархия           |  3/3 | На публичной карточке одно понятное главное действие.                                  |
| Дизайн: консистентность               |  3/3 | Используются существующие токены, кнопки и карточки.                                   |
| Дизайн: типографика                   |  3/3 | Название, дата и роль разделены по размеру и контрасту.                                |
| Дизайн: цвет и контраст               |  2/3 | Точный контраст нужно повторно проверить на физическом телефоне.                       |
| Дизайн: пространство                  |  3/3 | Из календарных и batch-форм убраны колонки филиалов.                                   |
| Дизайн: адаптивность                  |  2/3 | Есть mobile-компоненты, но финальная проверка после deploy ещё нужна.                  |
| Дизайн: обратная связь                |  3/3 | Ошибка роли выводится через `role=alert`, действие блокируется в pending.              |
| Дизайн: доступность                   |  2/3 | Кнопки имеют текстовые названия; нужно проверить touch target в браузере.              |
| Удобство: первый шаг гостя            |  3/3 | Гость видит «Зарегистрироваться на мероприятие», без развилки «Войти».                 |
| Удобство: возврат после регистрации   |  3/3 | Callback ведёт обратно к выбранному мероприятию.                                       |
| Удобство: вход администратора         |  3/3 | Текстовая ссылка ведёт в защищённую админ-панель, без смешения с клиентским сценарием. |
| Удобство: выход из админки            |  3/3 | Переход в расписание не завершает сессию.                                              |
| Удобство: управление ролями           |  3/3 | Назначение доступно прямо на карточке клиента и требует подтверждения.                 |
| Удобство: защита ручной карточки      |  3/3 | Ясно указано, что сначала требуется самостоятельная регистрация.                       |
| Удобство: форма события               |  3/3 | Нет лишнего выбора филиала в однобазовом MVP.                                          |
| Удобство: пакетный ввод               |  3/3 | Таблица короче на одну колонку и не запрашивает неактуальные данные.                   |
| Удобство: ошибки и ожидание           |  3/3 | Ошибки не скрываются, повторная отправка блокируется.                                  |
| Удобство: пустые состояния            |  2/3 | Текст есть, но его следует проверить с реальной пустой базой.                          |
| Выгода: публичность расписания        |  3/3 | Просмотр не требует регистрации.                                                       |
| Выгода: конверсия в запись            |  3/3 | Регистрация запрашивается только в момент ценного действия.                            |
| Выгода: единая клиентская база        |  3/3 | Роль и факт регистрации берутся из той же записи клиента.                              |
| Выгода: контроль владельца            |  3/3 | Только владелец может менять права администратора.                                     |
| Выгода: безопасность                  |  3/3 | Пароль не возвращается в список клиентов, владелец не понижается из списка.            |
| Выгода: скорость администратора       |  3/3 | Назначение роли не требует отдельного поиска или перехода.                             |
| Выгода: готовность к будущим филиалам |  3/3 | Связи данных сохранены, UI не усложняет MVP.                                           |
| Выгода: мобильная применимость        |  2/3 | Компоненты адаптивны, но нужен реальный проход на телефоне.                            |
| Выгода: понятность ограничений MVP    |  3/3 | Финансы, маркетинг и Mini App не выданы за готовую функциональность.                   |

Итог: дизайн 87,5% (21/24), удобство 93,3% (28/30), выгода 96,3% (26/27).
Порог пройден для проверочного URL. До переключения основного домена остаётся
проверить новый URL в desktop и на телефоне, включая назначение/снятие роли
тестового зарегистрированного клиента.

## UX-аудит: компактные карточки публичного расписания

Дата: 2026-10-14. Scope: только мобильная публичная выдача и возвращение
администратора в рабочую область. Это code-аудит перед проверочной публикацией;
визуальная проверка на физическом телефоне остаётся следующим шагом владельца.

| Принцип  |          Балл | Обоснование                                                                                                                                                                                                                |
| -------- | ------------: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Дизайн   | 22/24 (91,7%) | Карточка использует существующие цвета и типографику; длинное название обрезается в одну строку, не растягивая список.                                                                                                     |
| Удобство | 28/30 (93,3%) | В закрытой карточке остаются дата, время, название и спикер; все остальные данные доступны по понятному «Подробнее». Ссылка «Админ-панель» видна и на мобильной ширине, а доступ всё ещё проверяется защищённым маршрутом. |
| Выгода   | 25/27 (92,6%) | Четыре компактные карточки помещаются в типичный экран списка без потери пути к полной карточке и записи. Реальный размер на конкретном устройстве нужно подтвердить после deploy.                                         |

Итог: все три порога пройдены для проверочной публикации. Не менялись права,
данные, API и Mini App. P2: после просмотра на физическом телефоне при необходимости
скорректировать вертикальный ритм, не добавляя новых полей в закрытую карточку.
