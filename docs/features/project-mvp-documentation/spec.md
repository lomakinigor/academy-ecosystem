# Project MVP documentation — spec

## Problem statement

Нужна понятная владельцу конфигурация текущего MVP и честный roadmap полного продукта.

## Acceptance criteria

- Отдельно указаны реализованные, подготовленные в data model и планируемые функции.
- Описаны роли, основные маршруты, API, данные, окружение и deploy.
- Указаны ключевые ограничения и security/operational debt.
- Документ не содержит секретов, паролей, токенов и connection strings.

## Affected files

- Новый пользовательский паспорт: `docs/PROJECT_STATUS.md`.
- Артефакты процесса в текущей папке feature.

## Test plan

1. Сверить документ с существующими route/API/schema файлами.
2. Прогнать `pnpm test` и `pnpm typecheck` без изменений приложения.
3. Проверить diff на отсутствие secrets.

## Rollback

Удалить только новую документацию; работа приложения не затронута.

- [x] Цель, границы и критерии приёмки определены.
- [x] Нет изменения доменной логики, API или данных.
- [x] Риски и стратегия проверки описаны.
