# Публичная регистрация на мероприятие

## Проблема

На публичной карточке и в шапке «Войти» отвлекает от единственного нужного
первого действия: записи на выбранное мероприятие.

## Сценарий

Незарегистрированный посетитель открывает карточку и нажимает
«Зарегистрироваться на мероприятие». Он переходит на `/signup` с callback URL
исходной карточки. После регистрации автоматически возвращается к мероприятию.
В шапке публичной части нет кнопки или ссылки входа; закрытые маршруты по-
прежнему самостоятельно перенаправляют на `/login`.

## Acceptance criteria

- У гостя на карточке одно действие с точным текстом
  «Зарегистрироваться на мероприятие».
- Ссылка ведёт на `/signup?callbackUrl=/event/<id>`.
- В публичной шапке нет «Войти» и «Регистрация».
- В публичной шапке есть текстовая ссылка «Админ-панель» на защищённый маршрут
  `/admin/calendar`; это не вход и не регистрация.
- В административной шапке «Выйти из админ-панели» возвращает на `/` без
  завершения сессии. В MVP нет управления завершением аккаунта в интерфейсе.
- В списке «Клиенты» владелец видит роль зарегистрированного пользователя и
  может назначить либо снять права администратора. Незарегистрированная
  карточка не может получить права.
- В MVP в интерфейсе не показываются филиалы: нет фильтра, поля формы,
  колонки пакетного ввода и подписи на карточке. Поля и связи в данных
  сохраняются для будущего этапа.
- Состояния записанного пользователя, отмены и прошедшего мероприятия не меняются.
- Не меняются данные, API, права доступа или Mini App.

## Проверка и откат

Component test проверяет текст и callback URL. Existing auth и public calendar
tests остаются зелёными. Component tests также проверяют вход в админку и
выход из неё без server action. Откат — вернуть только UI-компонент и две точки
встраивания; данные не затрагиваются.
