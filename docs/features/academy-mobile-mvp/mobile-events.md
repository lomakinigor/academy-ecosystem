# Приоритет: создание и просмотр мероприятий

Владелец 13 октября 2026 изменил порядок: сначала все сценарии мероприятий в web, затем перенос проверенных сценариев в Mini App. Клиентскую базу/идентичность пока не расширяем. Защитная регистрация отложена, но её риск остаётся блокером полноценного публичного релиза.

## Discovery текущего шага

1. На телефоне администратору трудно просмотреть неделю: таблица шириной минимум 840 px.
2. Названия ограничены двумя строками, спикер обрезан; несколько мероприятий доступны только в узких ячейках.
3. На мобильном дни недели идут вертикально, все события видны полностью; desktop сохраняет недельную сетку.
4. Стиль/поля/серверные даты и филиальные данные сохраняем; голос/OCR/Telegram не включаем в этот шаг.
5. Альтернатива — горизонтальная прокрутка — уже есть и неудобна для выбранного телефонного сценария.
6. Риски: регрессия недельной навигации, скрытые события, длинные слова. Тестируем несколько событий в день, длинное название, предыдущую/следующую неделю.

## Acceptance и review

- Без фиксированной минимальной ширины 840 px; одна колонка дней на телефоне, семь на широком экране.
- Пн–Вс и выходные различимы, текущий день помечен.
- Названия/спикеры переносятся, мероприятия не сворачиваются, кнопка события имеет touch-height не менее 44 px.
- Навигация по неделям и открытие выбранного события сохраняются.
- Ручная/пакетная формы и публичный календарь — следующие шаги, не объявляются завершёнными по изменению одного компонента.

Spec review пройден: границы минимальны, негативные случаи описаны, DB/API не меняются. План: component red → responsive layout → календарные tests/typecheck → commit/push. Откат: вернуть layout компонента, без изменений данных.

## Выполненный шаг

- Red: новые тесты дня/пустого состояния падали до правки; прежняя навигация уже работала.
- Green: все 43 календарных теста прошли. Responsive layout убрал фиксированную ширину, показывается один столбец до lg breakpoint, на desktop семь.
- Самопроверка: server API, поля событий и бронирования не менялись; сортируются только локальные массивы дневной группировки, не исходный props-массив.
- В browser на 360px подтверждён прежний широкий календарь; после steering вкладка исчезла. Новый layout ещё не проверен в реальном браузере и не опубликован.
- Далее: адаптация одиночной/пакетной формы, ручная проверка на 360px, публичный просмотр и полный сценарий создания/редактирования web. Затем Mini App.
