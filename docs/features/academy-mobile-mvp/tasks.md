# План реализации: мобильный MVP Академии

Код не начинается до подтверждения этой спецификации.

Уточнение порядка от 13 октября 2026: приоритет — полный web-сценарий просмотра и создания мероприятий. Затем перенос в Mini App (начинать после приёмки web и разрешения владельца). Клиентская база/безопасная привязка отложены; замечания безопасности не сняты с release gate.

1. Добавить failing tests для прав клиентской базы и правил конфликта событий.
2. Добавить migration и Prisma-модели клиента/контактов, проверить сохранность
   существующих пользователей и бронирований.
3. Реализовать серверные операции клиентов с проверкой `BRANCH_ADMIN+`.
4. Добавить unit-тесты нормализации контактов. Безопасная привязка Telegram
   отложена вместе с Mini App до отдельного разрешения владельца.
5. Реализовать четыре раздела mobile-first admin-навигации и заглушки.
6. Перевести календарь на недельный вид, периодную загрузку и предупреждения
   о конфликтах; покрыть component-тестами.
7. Реализовать мобильный список и создание клиентов; покрыть RBAC и формы.
8. Прогнать typecheck, unit/integration/component tests, ручную мобильную
   проверку и e2e-путь сайта.
9. Только в последнюю очередь, после отдельного разрешения владельца,
   реализовать Telegram Mini App: клиентский маршрут, проверку `initData`,
   привязку аккаунта, переход в web-админку и e2e-проверку бота.
