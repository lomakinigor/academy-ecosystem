# Видимость пароля и права владельца

## Discovery и решения

1. Пользователь должен проверять введённый пароль на телефоне.
2. Сейчас login/signup всегда скрывают пароль, функции назначения администраторов нет.
3. Кнопка переключает password/text без изменения значения и без отправки формы.
4. Публичное расписание остаётся без входа; роли и безопасность пароля не меняются кнопкой.
5. Общий мастер-пароль для входа в чужие аккаунты не используем; нужен отдельный аккаунт владельца.
6. Владелец указал email в чате и подтвердил назначение/снятие администраторов только владельцем; все администраторы одного уровня. Email не публикуем в Git.

## Acceptance и spec review

- Вход и регистрация изначально скрывают пароль.
- Доступная кнопка «Показать пароль» открывает его, «Скрыть пароль» снова скрывает.
- Значение, autocomplete, required/minLength и отправка формы остаются прежними.
- Управление администраторами — отдельный шаг: нельзя давать эти права только на основании неподтверждённого email при регистрации. Нужна защищённая привязка владельца к существующей записи и проверка полномочий на сервере.

Review кнопки пройден: сценарии, совместимость и негативный случай (случайная отправка) определены. План: component-тесты red → два переключателя → web-тесты/typecheck → commit/push. Откат — revert commit, без БД.

Статус аккаунта владельца и назначения администраторов: ожидает отдельной безопасной реализации и настройки. Пароль пока не создан и не изменён.

## Проверка кнопки

- Red: оба теста не находили кнопку до реализации.
- Green: 82/82 теста авторизации, typecheck web успешно.
- Self-review: поля сохранили autocomplete, required, minLength и имя password; кнопка type=button не отправляет форму. Пароль хранится только в текущем поле, не выводится в логи или storage.
- Аккаунт владельца и назначение администраторов не объявляются готовыми. Перед сменой существующего пароля требуется уточнить намерение владельца.
