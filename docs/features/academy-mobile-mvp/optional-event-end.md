# Необязательное окончание мероприятия

## Problem framing / discovery

1. Администратор не всегда знает время окончания.
2. Сейчас форма требует конец, batch отклоняет пустой конец, API придумывает +2 часа.
3. Нужны ручное создание/редактирование и batch с известным началом и пустым окончанием.
4. Начало обязательно; известное окончание позже начала; «Весь день» сохраняет date-only диапазон.
5. Выбрано nullable end_at вместо фиктивной длительности и дополнительного флага.
6. Неизвестная длительность не позволяет надёжно проверить пересечения. Не обозначать её как бесконечную.

## Spec

Пустое end_at хранится как null. Поле очищается и при редактировании.
Новые формы не подставляют окончание. AI запрещено выдумывать конец.
Такие события показываются только в день начала; время отображается «HH:MM».
По уточнению владельца не показывать никаких подписей об отсутствующем окончании.
Запросы public/admin включают событие без окончания, если начало внутри периода.
Проверка точных пересечений для неизвестного конца не выполняется.
Существующие известные окончания и all-day события остаются без изменений.

Affected: Prisma Event, event schema/router, ручная/batch форма, AI prompt,
calendar/card/public detail, tests. Аддитивная по данным миграция снимает NOT NULL,
без переписывания существующих записей. API принимает null/отсутствие конца.

## Acceptance / test plan

- API создаёт null вместо +2 часа, update очищает конец.
- Ручная форма позволяет пустое окончание и повторно открывает его пустым.
- Batch сохраняет указанное начало с пустым окончанием.
- Известный конец <= начала по-прежнему ошибка, all-day требует диапазон.
- Событие без конца присутствует в календаре только в день начала.
- Карточка не показывает фиктивный конец.
- Tests/typecheck/diff review до commit/push; отдельный preview без продвижения main.

## Rollback

Откат приложения допускается только на версию с nullable-aware отображением.
Не возвращать NOT NULL, если появились null, не придумывать длительность для отката.
