# Общая область расписания web-MVP

## Discovery

1. Администратор должен вести все мероприятия в одном расписании.
2. Сейчас BRANCH_ADMIN ограничен филиалом, MASTER может писать события через API, UI требует выбор филиала.
3. Нужно общее чтение, редактирование и проверка пересечений для BRANCH_ADMIN+, общий список спикеров.
4. Схема и филиальные метки существующих записей сохраняются; остальные подсистемы не получают расширенные права.
5. Вместо глобального изменения всех ролей используем отдельную область для расписания/спикеров.
6. Главный риск — открыть запись обычному клиенту. Отдельно тестируем STUDENT с каждым academic_level и запросы без session.

## Spec и acceptance criteria

- Администратор любого филиала читает/редактирует/удаляет любое мероприятие, создаёт общее событие (branch_id=null).
- Старые параметры branch_id не сужают администратору общий список и проверку пересечений.
- MASTER/MAGISTER/FOUNDER при system_role=STUDENT не создают события или спикеров.
- Список спикеров общий для администраторов; прежние ограничения обычного пользователя сохраняются.
- Из админ-фильтров, одиночного и пакетного ввода убран выбор филиала. Редактирование не переписывает старую филиальную метку.
- Публичные фильтры и прочие API вне этого шага. Пользовательский публичный календарь будет проверен отдельно.
- Данные в БД не переносятся, миграция не нужна. Проверки API используют mock Prisma, production не изменяется.

## Review и план

Review пройден: границы согласованы владельцем, положительные/отрицательные сценарии описаны, обратная совместимость данных сохранена.

1. Изменить тесты устаревших правил и добавить негативные API-тесты → red.
2. Добавить локальную общую область и ограничить запись ролью → green.
3. Скрыть филиальные элементы админки, проверить component-тесты и typecheck.
4. Self-review diff, commit/push. Откат — revert commit, без изменений схемы.

## Результат проверки

- Red: 9 тестов старой области событий, 7 новых сценариев и тест скрытия филиала в форме падали до реализации.
- Green: 74/74 профильных API-теста, 40/40 тестов календаря; typecheck API/web прошёл.
- Полный API-набор: 105 passed, 2 pre-existing failures (ожидание DRAFT и отсутствие проверки end_at <= start_at). Исправляются отдельным шагом, релиз не выполнялся.
- Self-review: общий scope применяется только к event/user-speaker API; protectedBranchProcedure для других роутеров не менялся, филиальная метка сохраняется в редакторе.
- Ручная мобильная и production-проверка ещё не выполнены. Публичный UI по-прежнему требует отдельной проверки на соответствие единому филиалу.
