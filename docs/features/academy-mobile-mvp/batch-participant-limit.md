# Пакетный ввод: необязательное число мест

## Framing / discovery

1. AI вернул 0 для отсутствующего лимита, сохранение остановилось на positive validation.
2. Сейчас необработанное число передаётся в event.create; это могло произойти после создания предыдущих строк.
3. Отсутствие допустимого лимита должно оставаться пустым, без выдуманного числа мест.
4. Реальный лимит — положительное безопасное целое; 0/null/undefined/отрицательные/дробные/нечисловые ответы AI — не корректный лимит.
5. Выбрана единая нормализация на границе распознавания и перед batch save, а не ослабление API validation.
6. Эта правка не даёт транзакционности при сетевых ошибках и не устраняет уже созданные дубли.

## Spec / acceptance

- Распознавание отдаёт null для неподходящего значения; положительный целый лимит сохраняется.
- До начала создания весь выбранный список нормализуется, включая ответ старого parser.
- event.create получает undefined для отсутствующего лимита; строгий API остаётся неизменным.
- Без надписей о неизвестном лимите и без переписывания существующих мероприятий.
- Unit/API/component tests для 0, null, отрицательного, дробного, строки и корректного лимита.

## Scope / review

Helper в lib/events, AI route, batch modal, regression tests. DB migration не нужна.
Goal, negative cases, backward compatibility, tests и rollback описаны; spec review пройден.
Tasks: red tests → минимальная нормализация → green suites/typecheck → preview.
Rollback: revert commit; пользовательские записи не изменяются.
