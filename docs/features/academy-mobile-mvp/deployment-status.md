# Развёртывание web-MVP

## Конфигурация

В Vercel-проекте `academy-ecosystem` существуют production-переменные
`DATABASE_URL`, `AUTH_SECRET`, `AUTH_TRUST_HOST` и `OPENROUTER_API_KEY`.
Тип переменных — `sensitive`. Их значения не возвращаются CLI/API.
Пустое значение при выгрузке не доказывает отсутствие секрета.
Ранее сделанный вывод об отсутствующих ключах был ошибочным.

Используем существующие переменные непосредственно в окружении Vercel.
Не заменяем ключи и не копируем секреты в Git.

## Последняя попытка

Отдельная production-сборка с отключённым автоматическим назначением доменов
создана для применения схемы базы и сборки web-приложения.

- Deployment: `dpl_3SuRC4rquScoVmJUiXZB4U9Ck7ch`.
- Команда: `pnpm --filter @academy/db db:push && pnpm build`.
- Результат: `BLOCKED` до запуска сборки.
- Причина Vercel: автор коммита не имеет разрешения создавать deployment
  в этом проекте.
- Текущая Git-идентичность локального checkout: стандартная заглушка.
- Последующая проверка API после входа подтвердила: CLI-аккаунт
  `claudethird2026-1548` имеет подтверждённую роль `OWNER` в `igorsibola`.
  Различие имени аккаунта и пространства не означает отсутствие прав.
- Миграция базы не выполнялась; основной домен не переназначался.

После разрешённого владельцем входа локальная Git-подпись новых коммитов
настраивается на подтверждённые имя и email этого владельца вместо
шаблона `Your Name / you@example.com`. История не переписывается.
Затем повторяем сборку, обновление схемы базы и проверку web-приложения.
