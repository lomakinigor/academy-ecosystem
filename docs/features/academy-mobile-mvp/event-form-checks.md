# Форма мероприятия: дата и пересечения

## Discovery и scope

1. Проблема: администратор не видит день недели и рискует назначить две встречи одновременно.
2. Сейчас форма отправляет только начало; окончание при создании автоматически равно +2 часа, при редактировании сохраняется прежним.
3. Нужно явное окончание, день недели и предупреждение перед сохранением с подтверждением.
4. Используем существующий API конфликтов и существующие роли; Telegram, филиальные права и схема БД в этом шаге не меняются.
5. Альтернатива — блокировать пересечения — отвергнута владельцем. Выбран предупреждающий сценарий.
6. Риски: устаревший ответ проверки, недоступность API, неверный диапазон; проверяем заново при отправке, ошибки не закрывают форму.

## Acceptance criteria

- Новое событие получает редактируемое окончание +2 часа; редактор сохраняет исходное окончание.
- Выбранная дата подписана полным днём недели на русском.
- Компактная неделя Пн–Вс выделяет выбранный день и выходные.
- Окончание не позже начала: запрос сохранения не отправляется, показывается ошибка.
- API показывает названия пересекающихся событий и причину: спикер/площадка.
- При сохранении выполняется свежая проверка. Отмена подтверждения не вызывает mutation; согласие отправляет оба времени.
- При ошибке проверки форма остаётся открытой и предлагает повторить сохранение.
- Проверка выполняется в текущей серверной области доступа; переход к общей области всех филиалов остаётся отдельным шагом.
