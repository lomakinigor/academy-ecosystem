# Короткое название календаря

Уточнение плотности: все ячейки80px, дата24px, каждое название24pxбез крупных плашек. Две подписи помещаются; больше — внутренний вертикальный scroll, события не скрываются и доступны с клавиатуры. Нет изменений данных/API. Проверить одинаковый класс высоты и click editor. Tradeoff: цели24pxвместо44pxради явно запрошенной плотности, текст10–12px. Review scopeCSSтолько; rollback классов.

Проблема: count показывает занятость, но не помогает узнать мероприятие. Владелец подтвердил короткие смысловые подписи вместо count. Сохраняем фиксированные семь колонок и rolling month. Альтернатива числа отклонена; отдельные подписи позволяют напрямую открыть нужный editor без выбора дня.

Приёмка: каждое мероприятие отдельной кнопкой в дне, только краткая подпись, доступное имя содержит полный title/date. Дата отдельно позволяет создать ещё одно мероприятие. Длинное слово truncate, день растёт при нескольких событиях. Все дни многодневного event показывают одну подпись. Полное название не изменяется.

Данные: nullable Event.calendar_title, max40символов. Старые записи работают через deterministic suggestion: значимые слова после общих «семинар/занятие/путь», пример Велеса→Велес, Йога, Массаж; алгоритм эвристический, поле редактируемое. Не подключать LLM ради слова. Пустое поле означает автоматическую подпись, ручное поле не перезаписывается при правке title. API create/update поддерживают поле с прежними правами; public полноназвание неизменно.

Review: scope только calendar/editor и additiveDBcolumn; никаких клиентов/финансов/MiniApp. Edge cases пустая подпись, неизвестные названия, дубли слов, много событий, мобильная ширина. RollbackUI оставляет nullablecolumn и данные; не удалять. План: red helper/component/schema tests → helper+storage+form → green tests/typecheck → preview с идемпотентным ALTER TABLE ADD COLUMN IF NOT EXISTS → browser после входа владельца.
