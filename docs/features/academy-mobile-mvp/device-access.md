# Запоминание браузера и владельцы — согласованная спецификация

## Discovery

1. Пользователь хочет длительный вход на своих устройствах и расширение владельцев.
2. Сейчас JWT живёт 7 дней, все устройства запоминаются; владелец один через ENV.
3. Согласовано: личный браузер 90 дней; чужой — без длительного запоминания; совладельцы управляют админами.
4. Другой браузер входит в существующий аккаунт; регистрации дубля нет. Никакого fingerprint.
5. Используем JWT + отдельный HttpOnly session nonce cookie для режима чужого устройства.
6. Cookie зависит от домена; разные preview адреса требуют входа. Browser restore может сохранять session cookies; на чужом устройстве рекомендуется явный выход.

## Acceptance

- Личный вход до 90 дней с момента аутентификации, чужой максимум 8 часов и требует session nonce cookie.
- В формах login/signup есть «Не запоминать меня на этом устройстве», по умолчанию выключено.
- Пароль/nonce не попадают в localStorage или публичную session.
- Существующие JWT без новых claims остаются до старого срока; forged client update не меняет claims.
- DB-права обновляются при каждом API/server user check, не доверяем JWT для назначения владельцев.
- is_owner в User; первичный владелец активируется только узкой SQL по серверному OWNER_USER_ID.
- Новый владелец получает admin доступ; снять роль главного владельца может только он сам.
- Последнего владельца снять нельзя, конкурентные изменения сериализуются.
- Обычный админ не назначает владельцев, API защищает главного независимо от UI.
- Снятие владельца оставляет обычные admin права; admin права владельца нельзя снять в обход owner операции.

## Review / tasks

Цель, отрицательные случаи, совместимость и browser boundaries описаны. Gate пройден.
Red tests → сессии и формы → owner DB/API/UI → typecheck/full suites → UX review/preview.
Без Mini App, смены main domain, выдачи прав реальным людям или изменения паролей.
Rollback: nullable-compatible предыдущий preview; новый is_owner оставить в DB, не удалять данные.

## Проверка реализации

Session nonce задаётся сервером HttpOnly cookie без expires/maxAge; JWT имеет
абсолютный valid_until и encode ограничивает exp. Client session.update не меняет claims.
Назначение владельца сериализовано транзакцией, внутри повторно проверяется actor;
DB flag считывается на следующем API/server request, JWT не источник owner rights.
Bootstrap блокирует конкурентный первый запуск advisory lock и активирует первичного
владельца по OWNER_USER_ID только при первом добавлении колонки; последующие сборки
не возвращают снятые права. В rollback колонка сохраняется.
